# 초대/탐색 그래프 MVP 화면 스토리보드
> Created: 2026-09-13
> Last Updated: 2026-09-13

## 범위와 상태

**확정.** Instagram 없이 지인 확인 링크만으로 관계 그래프를 만드는 새 MVP의 화면
스토리보드다. [00_PRODUCT_DECISION_LOG.md 2026-09-13 항목](../01_Concept_Design/00_PRODUCT_DECISION_LOG.md)의
제품 결정을 화면 단위로 정리한다. 최초 12개 화면 시안을 검토한 뒤 사용자 여정 리뷰에서
소셜 로그인, 표시 이름, 재사용 지인 링크를 추가하고 도시 선택과 전체 그래프를 MVP에서
제외했다. 변경된 여정은 HTML 미리보기에도 반영했다.

기존 [00_SCREEN_FLOW.md](./00_SCREEN_FLOW.md)/[01_UI_DESIGN.md](./01_UI_DESIGN.md)가
다루는 "Instagram 파일 가져오기" 흐름은 이 결정으로 MVP 기본 경로에서 빠지며, 참고용으로만
남긴다.

## 핵심 원칙

- **관계를 만드는 링크(지인 링크)**와 **거리를 확인하는 링크(공개 링크)**를 완전히
  분리한다. 공개 링크는 몇 명이 방문하든 절대 edge를 만들지 않는다.
- 지인 링크는 한 사람이 실제 지인 여러 명에게 재사용해서 보낼 수 있다. 각 수신자가
  관계를 확인할 때마다 링크 소유자와 수신자 사이에 edge가 하나씩 생긴다.
- 로그인은 카카오·Google을 제공해 동일 사용자를 기존 participant에 연결한다(2026-09-16
  해외 확장 결정으로 Google 추가, `00_PRODUCT_DECISION_LOG.md` 참고). 같은 사람이
  두 제공자로 각각 로그인하면 서로 다른 participant로 취급한다. 표시 이름은
  사용자가 직접 입력하며 로그인 식별자와 분리한다.
- 두 사람 사이의 경로 위 중간 사람은 이름은 물론 존재 자체도 공개하지 않는다(점으로만
  표시).

## 카피 원칙

- **거리 숫자를 `3단계`처럼 단독으로 결과화하지 않는다.** 항상 사람을 거치는
  관계라는 의미가 문장 안에서 드러나게 한다 ("몇 사람을 거치면 닿는지"로 번역해서
  보여준다).
- **노드 수와 "거치는 사람 수"를 정확히 맞춘다.** `나 ─ ● ─ ● ─ 상대`는 중간에 점이
  2개이므로 "두 사람을 거치면"이다. 내부적으로 쓰는 그래프 거리(`distance`, edge
  개수)는 이보다 1 크므로(이 예시는 distance=3) 사용자에게 그 값을 그대로 노출하지
  않는다 — `사람 수 = distance - 1`. 기존 [LivePairPage.tsx](../../apps/web/components/LivePairPage.tsx)의
  `{distance - 1}명의 지인이 이어져 있어요` 계산과 동일한 규칙이므로 구현을 새로
  만들 필요는 없고 문구만 이 원칙에 맞춘다.
- **"헐" 같은 감탄사로 반응을 대신하지 않는다.** 결과는 차분하게 두고, 반응은 캡처해
  커뮤니티에 올리는 사용자 자신의 몫으로 남긴다.
- **통계 표시도 "다리/단계" 단위 대신 사람 표현으로 통일한다.** `직접 아는 사람 ·
  한 사람 건너 · 두 사람 건너`처럼. "단계"라는 단어 자체를 UI에서 거의 쓰지 않는
  것이 목표다 — 개발에서는 `distance`로 부르고, 사용자에게는 항상 "몇 명을 거치면
  닿는가"로 옮겨 보여준다.

## 제품 용어

한때 "인맥 지도"(사용자가 보는 결과물)/"인맥 그래프"(내부 데이터)를 핵심
용어로 도입하려 했으나 철회했다 — 결정 6번("인맥", "네트워크"류 어휘를
화면 문구에서 피한다)과 정면으로 부딪히기 때문이다. 대신 결과물에 이름을
붙이지 않고, 과정을 동사로 풀어서 설명하는 쪽을 택했다("내가 아는 사람 →
그 사람이 아는 사람 → ..."). "그래프", "인맥", "네트워크", "데이터" 중
어떤 것도 화면 문구에 쓰지 않는다. 홈의 최초 CTA는 **"시작해보기"**, 다른 사람의
결과를 본 뒤 참여하는 CTA는 **"나도 시작하기"**로 구분한다. 홈에서는 첫 행동을
간결하게 안내하고, 결과 화면에서는 이미 본 경험을 자신의 것으로 이어가게 한다.

관계를 묻거나 링크의 목적을 안내할 때는 홈의 "건너건너 아는 사이"와 연결되는
"몇 다리 건너 아는 사이일까?" 표현을 쓴다. 다만 계산 결과는 다리 수를 숫자로
노출하지 않고, 위 원칙대로 "몇 사람을 거치면"류로 설명한다.

### 01. 첫 화면

```text
🍊 가이 알아?
🍊           🍊
      ?
나는 누구와 건너건너
아는 사이일까?
아는 사람들과 이어지다 보면
생각지도 못한 사람과 닿을지도 몰라요.
[ 시작해보기 ]
```
크림 배경. 감귤 둘 사이에는 아직 선이 없고, 캐릭터는 헤드라인보다 먼저
시선을 끄는 정도로 작게 둔다. "그래프", "인맥", "네트워크",
"데이터" 중 어떤 것도 쓰지 않고, 참여 → 발견이라는 과정만 두 문장으로
설명한다("아는 사람들과 이어지다 보면 / 생각지도 못한 사람과 닿을지도
몰라요"). 이 문구는 "참여하면 바로 찾아준다"가 아니라 "사람들이
참여하면서 점점 발견된다"는 걸 은근히 심어준다 — 초기엔 데이터가 적어
화면 10(연결 미발견)을 자주 보게 되므로, 그 결과가 실패가 아니라 당연한
과정이라는 걸 홈에서부터 학습시켜야 나중에 덜 허무하다. "Six Degrees of
Separation" 같은 용어는 쓰지 않는다.

### 01-1. 근거 설명 (홈 하단, 선택)

```text
세상은 생각보다 좁대요
몇 사람만 거치면 세상 누구와도
이어질 수 있다는 이야기가 있어요.
```
헤드라인·CTA로 3초 안에 이해가 끝나는 게 우선이라 이 설명은 버튼과 충분한
여백을 두고 별도 작은 콘텐츠 블록으로 구분하되, CTA보다 눈에 띄지 않도록
낮은 높이와 작은 내부 여백을 사용한다. `이야기가 있어요`로 완곡하게 표현해
검증된 사실처럼 단정하지 않는다. 숫자, 이론 이름, 각주 등은 노출하지 않아
가벼운 톤을 유지한다.

숫자나 이론 이름은 노출하지 않는다. 모든 화면(특히 결과 화면)은 카피 원칙대로
"몇 사람을 거치면"류로 옮겨 쓰고, 숫자를 "3다리"처럼 단독으로 노출하지 않는다.

### 02. 로그인과 표시 이름

동일한 사람이 여러 링크를 받아도 하나의 participant에 edge가 모이도록 처음 한 번만
로그인한다. 로그인은 원래 카카오만 제공했다 — 카카오는 사실상 한국에서만 쓰여서, 이
하나로 좁히는 것 자체가 콜드 스타트 전략(한 국가·커뮤니티에서 먼저 밀도를 만드는 것)과
맞았기 때문이다. 2026-09-16 해외 확장이 실제 목표로 확정되어 재검토 조건이 충족됐고,
Google을 추가 제공자로 도입한다(결정 로그의 2026-09-16 "로그인 제공자에 Google 추가"
항목 참고).

```text
🍊
먼저, 나를 알려주세요
내가 아는 사람들과 이어지려면
로그인이 필요해요.
[ 카카오로 계속하기 ]
로그인은 나를 구분하기 위해서만 사용해요.

어떤 이름으로 불릴까요?
아는 사람에게 보여줄 이름을 적어주세요.
[ 이름 또는 닉네임 ]
[ 이 이름으로 시작하기 ]
실명이 아니어도 괜찮아요.
```
소셜 계정 고유 ID는 동일인 판별에만 사용하고 화면에 노출하지 않는다. 표시 이름은
로그인 프로필에서 자동 수집하지 않고 사용자가 직접 정한다. 로그인 전 화면은 캐릭터,
짧은 로그인 이유, 카카오 버튼을 한 그룹으로 배치하며 카카오 버튼은 노란색 브랜드
스타일로 일반 메인 CTA와 구분한다. 표시 이름 설정 화면도 같은 온보딩 정렬을 쓰되
기존 입력창과 초록색 CTA 형태를 유지한다. 이름 입력 전에는 연한 초록색 disabled,
유효한 이름을 입력하면 진한 초록색 active 상태가 된다.

### 03. 지인 연결

직접 관계를 만드는 재사용 링크. 공개 거리 링크와 완전히 분리한다.

```text
실제로 아는 사람에게 이 링크를 보내보세요.
서로 아는 사이라고 확인하면 바로 이어져요.
[ 공유하기 ]
[ gai-ara.../invite/xxxx                         복사 ]
실제로 아는 사람에게만 보내주세요.
이어진 사람 보기 →
```
재사용을 허용하면서 1회용 토큰이 주던 피해 제한(유출돼도 edge 하나로 끝남)이
사라지지만, 사용 흐름을 막는 인원 상한과 만료 기간은 두지 않는다. 필요하면 소유자가
새 링크를 발급해 기존 링크를 폐기할 수 있는 서버 동작은 유지한다.

### 04. 지인 확인

```text
🍊     ?     🍊
수연님을 알고 있나요?
실제로 아는 사이라면 알려주세요.
[ 네, 알고 있어요 ]
잘 모르겠어요
```
두 감귤은 서로 바라보며 사이에는 작은 주황색 물음표만 둔다. 연결선은 그리지 않고
헤드라인 전체를 진한 초록색으로 표시한다. 외부 초대 진입 화면이므로 로고는 유지하되
`처음으로 →`는 제거한다. 여기서 확인되어야 edge가 생성된다(수신자 한쪽 확인,
재사용 토큰 — 근거는 결정 로그 2026-09-13 항목 참고). 로그인 전이면 현재
`/invite/{token}`을 `returnTo`로 보존해 카카오 로그인과 표시 이름 설정 뒤 자동 복귀한다.

### 05. 연결 완료

```text
🍊 ─────── 🍊
수연님과 연결됐어요.
이제 서로 아는 사이로 이어졌어요.
[ 나도 아는 사람에게 보내기 ]
이어진 사람 보기 →
```
04의 두 감귤과 같은 시각 언어를 이어받아 물음표 대신 얇은 연결선 하나를 보여준다.
중간 노드는 두지 않는다. 제공된 `connect.png`를 사용하고, 헤드라인은 04와 같은 진한
초록색으로 표시한다. 로고는 유지하되 `처음으로 →`는 제거한다. 첫 버튼은 수신자의
지인 연결 화면(`/connect`)으로 이어진다.

### 후순위. 도시 선택

```text
이 연결은 어디에서 시작됐을까요?
도시를 설정하면 '연결된 세상'에 내 점이 나타나요.
[ 도시 선택하기 ]
나중에
```
전체 그래프 시각화와 함께 MVP에서 제외한다. edge 생성과 거리 발견이 실제 반복되는지
확인하기 전에는 위치 데이터를 수집하지 않는다.

### 06. 내 연결 — 메인 화면

로그인 후 사실상의 홈 화면.

```text
      ●
      │
      ○
      │
● ── 🍊 ── ●
      나

여기서부터 이어져요
아는 사람들이 하나둘 참여하면
건너건너 이어진 사이도 나타나요.

[ 아는 사람에게 보내기 ]
실제로 아는 사이를 확인해요.

몇 다리인지 확인할 링크 공유하기 →
나와 건너건너 얼마나 가까운지 확인해요.
```
미니 그래프는 `gai-ara-mini-graph.svg`의 좌표와 색감을 참고한 React SVG 컴포넌트다.
실제 BFS 거리 1~3인 대표 관계를 최대 6개 고정 방향 슬롯에 배치하며, 데이터가 없으면
중앙 감귤과 `나`만 표시한다. 중간 노드와 끝 노드는 이름 없는 원으로만 표현하고 참여자
ID나 실제 경로를 클라이언트에 전달하지 않는다. 화면 진입과 탭 focus/visible 복귀 때
결과를 자동으로 다시 불러오므로 `다시 확인하기` 버튼은 두지 않는다.

두 번째 행동을 누르면 같은 화면 안에 `몇 다리인지 확인해볼까요?` 영역이 펼쳐진다.
Web Share API를 우선 사용하며, 말줄임 URL과 별도 `복사` 버튼, 잠시 표시되는
`✓ 복사됨` 피드백을 제공한다. 사용자 화면에는 `지인 링크`, `공개 링크`라는 내부 용어를
노출하지 않는다.

### 07. 몇 다리 확인 링크 펼침 (화면 06의 상태)

별도 페이지가 아니라 화면 06의 두 번째 행동을 누르면 미니 그래프와 기존 내용을
그대로 둔 채 아래쪽에 자연스럽게 펼쳐지는 상태다. 같은 행동을 다시 누르면 접힌다.

```text
몇 다리인지 확인할 링크 공유하기 ↑
나와 건너건너 얼마나 가까운지 확인해요.

──────────
몇 다리인지 확인해볼까요?
이 링크를 공유하면
나와 몇 다리 건너 아는 사이인지 확인할 수 있어요.

[ 공유하기 ]
[ gai-ara.../r/xxxx                         복사 ]
```
`공유하기`가 Primary CTA이며 모바일에서는 Web Share API를 우선 사용한다. URL 상자는
보조 행동으로 작게 두고 화면에는 말줄임 형태를 표시하지만 clipboard에는 전체
`/r/{token}` URL을 쓴다. 복사 성공 뒤에는 잠시 `✓ 복사됨`을 표시한다. 별도 카드나
modal을 붙이지 않고 여백과 얇은 구분선만 사용한다. 이 링크로 들어온 사람은 절대로
자동으로 직접 아는 사이가 되지 않는다. `/connect` → `/invite/{token}` 흐름과 token,
route, 동작을 공유하지 않는다.

### 07-1. 내가 발견한 사이들 (`/connections`)

화면 06에서 "이 링크로 만난 사람 N명 보기"를 누르면 오는, 자기 공개 링크로 지금까지
발견된 사이들을 다시 구경하는 화면. 목록이 아니라 "나"를 중심으로 거리만큼 점을
거쳐 뻗어나가는 작은 가지(spoke) 하나씩으로 보여준다.

```text
건너건너 만난 사람들
지금까지 발견된 사이예요.

        🍊
     나
  ○         ●(하은)
       ●(수연)
아직 못 찾은 시도 2건이에요.
```

`connected`이고 distance가 있는 결과만 가지로 그린다 — 미발견 시도는 그림에 넣지
않고 개수만 그림 아래 작은 문구로 덧붙인다. 가지 하나는 `나 ─ ○ ─ ○ ─ ●`처럼
(distance - 1)개의 빈 점과 마지막 실제 노드(방문자 표시 이름)로 이어지고,
가지가 여러 개면 중심 둘레에 각도를 나눠 배치해 겹치지 않게 한다. 빈 점에는
어떤 라벨도 붙이지 않는다 — 경로 위 중간 사람은 이름은 물론 존재 자체도
공개하지 않는다는 원칙이 여기서도 그대로 적용된다(중간 점이 몇 명인지는
보이지만 누구인지는 절대 보이지 않는다). 화면 06의 옛 1:1 링크(`pairInvites`)
요약은 여기서 완전히 제거됐다 — 06과 같은 이유로, 지금 서비스의 기본 흐름은
재사용 지인 링크(직접 연결)와 공개 링크(거리 확인) 두 종류뿐이다.

### 08. 공개 링크 진입

```text
🍊       🍊
    ?
{표시 이름}님과 나는
몇 다리 건너 아는 사이일까?
서로 모르는 사이여도
생각보다 가까울 수 있어요.
[ 몇 다리인지 확인하기 ]
```
링크 소유자의 표시 이름이 없으면 `우리, 몇 다리 건너 아는 사이일까?`로 보여준다.
다른 화면의 같은 일러스트레이션에는 영향을 주지 않고, 화면 08의 궁금해하는 두 감귤만
기존 크기보다 약 12.5% 작게 배치한다. 헤더에는 로고만 두고 `처음으로` 행동은 노출하지
않는다.
로그인 여부와 관계없이 먼저 이 화면을 보여준다. 처음 온 사람이 CTA를 누르면 현재
`/r/{token}`을 `returnTo`로 보존한 채 로그인과 표시 이름 설정으로 이동한다. 원래 링크로
복귀하면 CTA에서 시작된 확인 의도를 한 번만 소비해 자동으로 거리를 계산한다. CTA를
누르지 않은 로그인 사용자의 일반 `/r` 직접 방문에는 자동 계산하지 않으며, `/r` 방문이나
로그인만으로 직접 아는 사이를 만들지 않는다.

### 09. 연결 발견 — 핵심 화면

```text
생각보다 가까웠어요.
🍊 ─ ● ─ ● ─ 🍊
나              상대
두 사람을 거치면 서로 닿아요.
[ 결과 공유하기 ]
나도 시작하기
```
중간 사람은 이름을 보여주지 않고 경로(점 개수)만 보여준다. 점 개수와 "거치는 사람
수" 문구는 항상 일치해야 한다(카피 원칙 참고 — 이 예시는 점 2개이므로 "두 사람을
거치면"). `나 → ● → ● → 상대` 순서로 선이 켜지는 애니메이션을 준다. 최종 시안에서는
평소의 크림 톤 대신 화면 전체를 짙은 남색/검정 배경으로 바꿔 이 순간만 분위기를
확실히 전환했다 — 나머지 화면은 전부 크림 톤을 유지하므로 이 화면의 대비가 더
도드라진다. 이 화면이 서비스의 WOW moment다.

### 10. 연결 미발견

초기에는 이 화면을 가장 많이 보게 되므로 실패처럼 보이면 안 된다. 이 결과는
"두 사람이 연결되어 있지 않다"는 단정이 아니라 "현재 참여한 사람들의 데이터
안에서 아직 경로를 찾지 못했다"는 뜻이다 — 헤드라인·설명 문구·코드 모두
이 의미를 지켜야 한다(2026-09-13 개정, TASK-010).

```text
🍊    · · ·    🍊
아직 연결을
찾지 못했어요
현재 참여한 사람들 사이에서는 아직 이어지는 길을 찾지 못했어요.
아는 사람들이 더 참여하면 결과가 달라질 수 있어요.
[ 나도 시작하기 ]
```
실패한 방문자를 그래프 구축자로 전환하는 화면이다. 일러스트는 화면 08과 같은
`curious` 캐릭터를 재사용하고, 가운데는 사람 노드 없이 점 세 개(`···`)만
넣어 "아직 길을 찾지 못함"을 담백하게 표현한다. 빨간색·경고 아이콘·에러
문구는 쓰지 않는다. "다시 확인하기" 재시도 버튼은 두지 않는다 — 같은
데이터로 다시 계산해도 같은 결과만 나오고, 다음에 `/r/{token}`에 다시
들어오면 그때 최신 데이터로 자동 재계산되기 때문이다.

### 11. 공유 카드

별도 화면이라기보다 바이럴 광고판. 서비스 화면과 동시에 설계한다 — 커뮤니티에서
처음 보는 화면이 홈이 아니라 이 이미지일 가능성이 높다.

```text
생각보다 가까웠어요.
🍊 ─ ● ─ ● ─ 🍊
두 사람을 거치면 서로 닿아요.
가이 알아?
```
설명을 많이 넣지 않는다. 서비스 화면에서는 공개 링크 소유자의 표시 이름을 보여줄 수
있지만, 외부 공유 이미지에서는 조회한 두 사람의 이름을 모두 제외한다.

### 후순위. 연결된 세상

첫 MVP 검증에서는 화면과 위치 수집을 모두 제외한다. 이후 메인 플로우와 분리된 진입점
(`◉ 지금 연결된 세상`)을 누르면 크림 UI에서 완전히
검은 화면으로 전환되는, Obsidian 그래프 뷰 같은 전체 네트워크 시각화. 일정 규모
이상에서만 실제 그래프를 제공한다.

```text
🔒
지금은 준비 중이에요.
더 많은 사람들이 모이면
연결된 세상을 보여드릴게요.
```
초기 베타처럼 참여자가 적을 때는 위와 같은 잠금 상태로 보여준다 — 화면 자체를
숨기거나 실제 참여자 수("지금 12명이 연결되어 있어요")를 그대로 드러내는 대신,
자물쇠 아이콘과 "준비 중" 문구로 기능의 존재는 알리되 현재 규모를 정직하게 보여준다.
일정 규모(예: 참여자 수백 명) 이상이 되면 잠금이 풀리고 실제 그래프가 열린다.

```text
   ·────·  ·
·──●──·──·──●──·
  ╲──●──·──●───·
·──●──╲╱──·──●──·
  ·──·──🟠──·──·
·──●──·╱╲──●───·
지금 N명이 연결되어 있어요
              ◎ 내 위치
```
잠금이 풀린 뒤의 화면. 사람 = 작은 점, 관계 = 얇은 선, 클러스터 = 은하, 나 = 밝은
오렌지 노드. 새 연결이 확정될 때 점 등장 → 선 생성 → 클러스터 연결이 실시간으로
보인다. 노드에는 어떤 개인 식별자도 표시하지 않는다 — 오직 "내 위치"만 강조하고
그 외에는 익명 점이다. 사용하는 화면이 아니라 서비스가 살아 움직이는 걸 구경하는
화면이다. 잠금 해제 기준(정확한 참여자 수)은 구현 단계에서 정한다.

**v2 방향(잠금 해제 후, 지금 구현 범위 아님)**: 추상 은하 그래프 대신 검은 배경 위
3D 지구 + 국가/도시 단위 빛으로 표현한다 — "사람들이 실제 지구 위에서 연결되고
있다"가 바로 읽힌다. 줌 단계는 지구 → 국가 → 도시 클러스터 → 개인 노드 순으로
내려간다. 국가 간 연결은 지구 표면을 따라 얇은 곡선(arc)으로, 새 연결이 생기면
광점이 곡선을 따라 이동한 뒤 양쪽 노드가 잠깐 빛나는 연출을 준다. 기술 후보는
`Globe.gl`(지구·점·arc를 빠르게 구성)로 시작해 필요하면 `Three.js`로 비주얼을
고도화하는 조합이고, 노드 배치는 `3d-force-graph`/`Sigma.js`+`Graphology` 같은
평면 force-graph 계열도 검토했으나 "사람 = 지구 위에 사는 존재"라는 컨셉과의
정합성 때문에 지구 메타포 쪽을 우선한다. Unity 등 게임 엔진은 모바일 웹 진입
속도·번들 크기 부담이 커서 쓰지 않는다. 노드가 수십만 단위로 커지면 전체 렌더링
대신 클러스터/LOD 방식으로 전환해야 하지만, 초기 베타 규모에서는 고려하지 않는다.
메인 "내 연결" 화면(06)에는 이 3D 표현을 절대 넣지 않는다 — 가이 알아 자체는
가볍고 즉각적인 2D를 유지하고, 이 화면만 압도적인 톤으로 대비를 준다.

**위치 데이터 원칙**: 정확한 GPS·주소는 어떤 경우에도 수집·저장하지 않는다.
국가+도시 단위까지만 받고(05-1 참고), 같은 도시의 여러 사용자는 실제 좌표가 아니라
도시 영역 안에서 시각적으로 흩뿌려 표시한다. 확대하지 않은 상태에서는 도시 단위
집계("서울 2.4K")만 보여주고, 개별 노드로 분해되어도 이름은 여전히 공개하지
않는다 — 관계 데이터와 정밀 위치 데이터가 결합되면 민감도가 크게 올라가므로, 이
원칙은 다른 개인정보 원칙과 동급으로 취급한다(`AGENTS.md` §1, 결정 로그의 재검토
대상).

## 링크 두 종류와 기존 코드 매핑

Context Receipt(2026-09-13, 구현 착수 전) 조사 결과, 아래 두 개념은 이미 있는
테이블/API와 거의 그대로 대응된다 — 새 개념을 새로 만드는 게 아니라 기존 것의
의미를 확정하는 작업에 가깝다.

- **지인 링크(생성)** = 현재 `pairInvites` 기반 최소 구현은 accept를 edge로 사용하지만
  토큰이 1회용이다. 확정된 여정은 소유자별 재사용 링크와 수신자별 확인 기록이 필요하므로
  기술 명세와 저장 구조를 다시 설계해야 한다.
- **공개 링크(탐색)** = `referralLinks`/`referralVisits` 테이블 + `/api/referral-link`,
  `/api/r/:token`, `/api/r/:token/result`. 이 경로는 이미 지금도 방문 로그만
  남기고 edge를 만들지 않으므로, "공개 링크는 절대 edge를 안 만든다"는 원칙을
  코드 변경 없이 이미 만족한다.

## 전체 사용자 루프

```text
내 연결 → 재사용 지인 링크 공유 → 지인 참여 → edge 생성 → 그래프 성장
  ├─ 또 지인에게 공유 ─┐
  └─ 공개 링크 공유 ──┼─ 커뮤니티 → "건너건너 연결됐을까?" → 발견 / 미발견(내 연결 시작)
                      └─────────────── 그래프 성장
```
모든 행동의 결과가 뒤에서 하나의 `연결된 세상` 그래프를 계속 키운다.

- 화면 06(내 연결 메인)은 `/result`(`ResultScreen.tsx`)에서 실제 BFS 거리 표본을
  `MiniConnectionGraph`의 6개 고정 슬롯에 익명으로 그린다. 숫자 통계는 제거했고,
  `/connect`로 가는 "아는 사람에게 보내기"와 화면 안에서 펼쳐지는
  "몇 다리인지 확인할 링크 공유하기 →"를 서로 다른 설명과 함께 제공한다.
- 화면 07은 별도 route나 페이지가 아니라 화면 06의 인라인 펼침 상태로 구현했다.
  미니 그래프를 유지한 채 Web Share 중심 CTA와 `/r/{token}` 복사 보조 행동만 보여준다.
- 화면 08(공개 링크 진입)·09(연결 발견)·10(연결 미발견)은 TASK-007로 구현
  완료 — `ReferralLanding.tsx`가 Instagram 업로드 기반 옛 흐름(`ImportOnboarding`)을
  걷어내고, 세션과 무관하게 먼저 08의 확정 카피(owner 표시 이름이 있으면 개인화된
  "OO님과 나는 몇 다리 건너 아는 사이일까?"로 치환)를 보여준다. 화면 08의 감귤
  일러스트레이션은 이 화면에서만 약 12.5% 줄이고 헤더의 `처음으로`는 숨긴다.
  비로그인 사용자가 CTA를 누르면 `/login`을 거쳐 원래
  `/r/{token}`으로 복귀하며, 이 CTA에서 시작된 확인 의도를 한 번만 소비해 자동으로
  거리를 조회한다. 일반 로그인 사용자의 직접 방문은 계속 화면 08에서 기다린다. 결과가
  `connected`면 화면
  09를(짙은 배경으로 전환, 기존 `ConnectionDiagram`·새 `formatIntermediaryPhrase`
  재사용), `unreachable`이면 화면 10을 그대로 렌더링한다. "나도 시작하기"는
  세션의 `hasDisplayName` 여부로 `/connect`/`/login`을 가른다. 화면 11은
  `apps/web/app/r/[token]/page.tsx`의 OG `title`/`description`만 새 카피로
  갱신했고, 실제 카드 이미지 생성은 후순위로 남겨뒀다(기존 정적
  `gamgyul-wave.png` 재사용).
- 화면 07-1(내가 발견한 사이들, `/connections`)은 TASK-006으로 구현 완료 —
  `ConnectionsList.tsx`가 옛 텍스트 리스트(공개 링크 방문 기록 + 옛 1:1
  `pairInvites` 요약)를 걷어내고, `/api/referral-link`의 `visits`만으로 "나"
  중심 가지형(spoke) 미니 시각화를 그린다. `connected`·distance 있는 결과만
  가지로 그리고, 나머지는 그림 아래 "아직 못 찾은 시도 N건" 문구로만 반영한다.
  순수 CSS(절대 위치)+SVG(`<line>`)로 구현했고 새 의존성은 추가하지 않았다.
